# Troupe

Mobile app for finding project collaborators, built with an Expo (React Native) client and a Fastify/Prisma API server backed by Supabase (auth, Postgres, storage, realtime) and Redis rate limiting.

## Tech Stack
- Client: Expo SDK ~55.0.12, React Native 0.83.4, React 19.2.0, TypeScript, Expo Router, Expo Notifications, Expo Location, AsyncStorage, Supabase JS, Expo Image.
- Server: Fastify 4, TypeScript, Prisma, PostgreSQL (Supabase), Zod validation, Redis (rate limiting/cache), Supabase Storage, Expo push API.
- Tooling: Vitest, TSX, Supabase CLI, Docker (for local Postgres via Supabase).

## Architecture
- Monorepo: `client` (mobile app) + `server` (API).  
- Auth: Supabase email/password + Google OAuth handled in the client; server verifies JWTs via Supabase service key.  
- Data/API: Client calls Fastify REST endpoints for feed, likes/matches, messages, profile, uploads, notifications, and location.  
- Realtime: Supabase Realtime subscriptions on Postgres tables for match/message updates (no socket.io layer).  
- Storage: Profile pictures stored in Supabase Storage (`profile-pictures` bucket) via signed upload URLs; URLs are signed on the server for public/profile views.  
- Caching/Rates: Redis-backed rate limiting; feed/profile caches in Redis where available.

## Repository Layout
- `client/app` – Expo Router routes (tabs: feed, likes, messages, profile; onboarding; auth; message thread/profile views).
- `client/src` – auth (Supabase client/provider), services (api, matching, profile, upload), hooks (feed, likes, matches, location, profile picture upload), notifications, location provider, UI components, utils, constants, theme.
- `server/src` – routes, services, middleware (auth, rateLimit, sanitizeLocation), rate-limiting engine, utils (profile pictures, cache invalidation, sanitization), Prisma client, Supabase admin client.
- `server/prisma` – Prisma schema and migrations.
- `supabase` – CLI config, migrations, seed.

## Setup

### Prerequisites
- Node.js ≥ 18
- Docker + Supabase CLI (for local Postgres)
- Redis instance (Upstash or local) for rate limiting
- npm

### Server (local)
1) `cd server && npm install`  
2) Start local Supabase Postgres: `npx supabase start` (or point env vars at an existing Supabase project).  
3) Copy `.env.example` to `.env.local` and fill in the required server environment variables.
4) Generate client & seed test data: `npm run db:local:setup` (creates `.env.test`, pushes schema, generates Prisma client).  
5) Run the API: `npm run dev` (loads `.env.local`).

### Client (local)
1) `cd client && npm install`  
2) Create `.env` (or `.env.local`) and fill in the required client environment variables.
3) Start Expo: `npx expo start` (use a physical device for push notifications).

## Features
- Supabase authentication (email/password, Google OAuth).
- Discovery feed with swipe/like/pass and rate limiting.
- Likes inbox and match creation.
- Messaging via REST endpoints plus Supabase Realtime subscriptions.
- Profile management: bio, skills, interests, projects, experiences, GitHub username, location preferences.
- Profile picture upload with signed URLs and server-side validation/sanitization.
- Location sharing with HMAC-signed updates and background updates (Expo Location).
- Push notification registration and per-match notification preferences (Expo push).
- Offline aids: feed cache in AsyncStorage (messages are online-only today).

## API (selected endpoints)
- Auth: `POST /auth/signup`, `GET /auth/me`
- Feed: `GET /api/feed`
- Likes: `POST /api/likes`, `GET /api/likes/received`, `POST /api/likes/:id/accept|decline`
- Matches: `GET /api/matches`, `GET /api/matches/:matchId`, `POST /api/matches/:matchId/unmatch|block|unblock|hide`
- Messages: `GET /api/matches/:matchId/messages`, `POST /api/matches/:matchId/messages`, `PATCH /api/matches/:matchId/messages/:messageId`, `PATCH /api/matches/:matchId/messages/:messageId/delete`
- Profile: `GET /api/profile/me`, `PATCH /api/profile/me`, `GET /api/profile/:userId`, `DELETE /api/profile/me`
- Uploads: `POST /api/upload/profile-picture/request`, `POST /api/upload/profile-picture/confirm`
- Notifications: `PATCH /api/notifications/push-token`, `DELETE /api/notifications/push-token`, `GET/PUT /api/notifications/preferences/:matchId`
- Location: `GET /api/users/me/location-secret`, `PATCH /api/users/me/location-settings`, `PATCH /api/users/me/location`

## Design Decisions & Trade-offs
- Supabase Auth + Fastify backend keeps auth centralized while enabling custom business logic; Realtime is used via Supabase rather than socket.io.
- Redis is mandatory in production for rate limits and cache; code falls back to in-memory in dev.
- Profile pictures are stored in Supabase Storage; signed URLs are generated per request (performance vs. security trade-off).
- Messages and matches are paginated REST endpoints (cursor-based) to keep lists performant.

## Testing
- Server: `npm test` (uses `.env.test` generated by `npm run db:local:setup`; runs Vitest integration/unit suites).
- Client: `npm run test`, `npm run test:unit`, `npm run test:components` (Vitest; mostly unit-level).
- No published coverage numbers; integration/e2e testing is not yet implemented.

## Deployment Notes
- Provision Postgres (Supabase), Redis, and Supabase Storage bucket `profile-pictures`.
- Set all required env vars; run `npm run build && npm run start` (server) with a process manager.
- For push notifications, ensure the Expo project ID in `app.json` matches the deployed app and use physical devices.
- Configure Supabase Realtime replication for `Match` and `Message` tables if relying on live updates.
